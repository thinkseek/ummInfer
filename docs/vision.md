# ummInfer 终局愿景与联合训练演进蓝图（以终为始）

> 本文记录 ummInfer 从「多模态原生推理引擎」迈向「原生全双工、自主模态选择、训推消融闭环的统一多模态系统（UMM）」的终局目标、核心场景与分阶段演进路线。
>
> 当前已落地能力的逐行代码锚点见 [feature-map.md](feature-map.md)，当前工程架构见 [architecture.md](architecture.md)，既有阶段门禁与实测边界见 [roadmap.md](roadmap.md) 与 [rl-phase2.md](rl-phase2.md)。

---

## 1. 终局愿景（North Star）

打造一个**低延迟、高流畅度的原生统一多模态交互引擎**——不再依赖脆弱的多轮 Agent 胶水编排，而是让统一多模态系统与引擎协同原生完成**“看、听、想、说、画、动”**：

1. **流畅高速的图文视混排输出**：
   - 在单一连续响应流内，边思考边流畅输出结构化 Markdown 正文、高质量静图与动态视频片段；
   - 静图与视频在同一语义插槽内可原位无缝互换（例如 FLUX.2 静图一键驱动 Wan2.2 原生 I2V 动画化），画面风格与叙事上下文高度一致。
2. **自主模态选择（Autonomous Modality Routing）**：
   - 由模型自身原生判断“此处最适合纯文字解释、插一张示意图、还是生成一段动态视频”，自动决定视觉密度与呈现形式，做到**该图则图、该动则动、不冗余不割裂**。
3. **全局全双工语音交互（Global Full-Duplex Voice）**：
   - 语音作为全局一等通道贯穿整个对话生命周期：亚秒级首音响应、声画同步播报；
   - 支持真正的全双工打断（Barge-in）：用户随时插话，客户端与引擎毫秒级中止在途播报与无效生成，保留已消费上下文并自然承接新意图。
4. **全模态任意输入（Any-to-Any Input）**：
   - 原生支持文本、实时流式语音、单图/多图以及**视频输入**（连续帧与时空压缩表征），支撑“边看画面/视频、边语音讨论、边实时出图/动画演示”的闭环体验。
5. **原生能力替代复杂 Agent 编排（Showcase 范式跃迁）**：
   - 现有大量“图文并茂、边讲边演示”的高光展示需要多轮 Agent 规划、外部工具调用与多次串行等待；
   - 通过**原生统一多模态架构 + 联合后训练（Joint Post-Training）**，把模态决策、视觉构图、动态演进与语音韵律内化进模型与引擎协同路径中，达到数量级的流畅度与端到端一致性提升。

| Showcase | 用户输入 | 引擎原生输出体验 | 与传统多轮 Agent 方案的本质差异 |
| --- | --- | --- | --- |
| **活教材 / 纪录片式实时讲解** | 语音或文字提问（如“讲清黑洞吸积盘与引力透镜”） | 亚秒级开启连贯语音播报与结构化 Markdown 正文；讲到关键节点自动原位插入示意图与动态模拟视频，点击任意静图可原位动画化 | 单流原生交错生成与并行渲染，无多轮工具调用停顿，文本/语音/图像/视频共享同一叙事逻辑 |

## 3. 从当前基座到终局的三阶段路线

### Stage A — 原生五模态执行基座（已完成，Wave 1–11）
- 原生 C++/CUDA 五模态服务链路稳定运行（ASR + VLM + FLUX.2 图像 + 流式 TTS + Wan2.2-TI2V-5B 原生 T2V & 首帧锚定 I2V）。
- 交错叙事编排（边写边派发视觉插槽 + 全局流式 PCM16 语音 + `POST /v1/visual/render` 原位图↔视互换与 `Animate → Video`）。
- Web UI 与 macOS `ummmlx` 双端支持均衡 Markdown 排版与完整多模态交互。

### Stage B — 全双工语音、视频输入与引擎深度协同（下一代运行时）
1. **全双工语音与毫秒级打断（Full-Duplex Barge-in）**：
   - 统一服务端/客户端 VAD 与双向实时音频通道；
   - 打断信号沿控制面瞬间广播至 VLM、TTS 与在途图像/视频 Stage，确保 `in_flight` 归零、显存即时回收，并精确截断已播报文本进入多轮历史。
2. **原生视频输入管线（Video Understanding Input）**：
   - 统一 `/v1/chat/completions` 视频输入协议（抽帧/关键帧预算、时空 Token 压缩、长视频分段）；
   - 打通“视频输入 → VLM 理解 → 图文视交错回复 + 语音播报”端到端路径。
3. **更高保真的视觉连续性与性能**：
   - I2V 宽高比保真（中心裁切/原生宽幅生成，消除方图转宽屏拉伸）；
   - 跨槽位风格/角色一致化参考传递；
   - 进一步压缩 TTFT / TTFA 与首帧视觉延迟，推进原生统一多模态模型与跨 Stage CUDA IPC 零拷贝数据面。

### Stage C — 联合训练、联合后训练与可消融实验套件（Joint Training & Ablation Suite）

遵循 [roadmap.md](roadmap.md#phase-6--rl-rollout-trajectory-reward-and-training) 与 [rl-phase2.md](rl-phase2.md) 的架构原则：**推理引擎（`ummInfer`）不耦合优化器状态，而是作为高吞吐、可复现的 Rollout 与在线评测目标**，通过标准轨迹导出与权重热加载边界对接独立训练套件。

#### 3.1 联合训练与后训练逻辑
1. **联合 SFT（冷启动与格式内化）**：
   - 构建高质量“图文视交错 + 口语化语音文本”联合轨迹数据，学习原生结构化模态切换与高质量视觉描述，消除生硬模板感。
2. **联合后训练 / 多模态强化学习（Joint RL / GRPO / DPO）**：
   - **自主模态选择奖励**：奖励在需要直观视觉辅助处触发图/视频、在纯抽象推理处克制使用视觉的决策，并引入端到端延迟/算力代价惩罚；
   - **跨模态一致性奖励**：联合评估正文语义、图像内容、I2V 运动合理性与语音文本流畅度；
   - **全双工轮次与打断奖励**：评估打断响应及时性、上下文衔接自然度与无冗余复读。

#### 3.2 完整消融实验体系（Ablation Matrix）
训练套件必须把关键架构与算法选择设计为**单变量可切换、配置驱动、全指标可复现**的消融维度：

| 消融维度 | 对照基线（Baseline） | 实验变体（Variants） | 核心观测指标 |
| --- | --- | --- | --- |
| **模态路由机制** | 启发式 Prompt/Tag 解析 | 联合 SFT 隐式路由 / RL 策略路由 / 轻量级路由头 | 模态选择 F1、冗余出图率、TTFT |
| **视觉呈现形态** | 纯文本 / 仅静图 | 图+T2V / 图+原生 I2V（首帧锚定） | 图文相关性、首尾帧一致性、用户盲评胜率 |
| **语音协同策略** | 整段生成后播报 | 句级流式 TTS / 全双工打断 / 原生音频 Token | TTFA、断流率、打断响应延迟 |
| **视频输入表征** | 均匀低帧率抽帧 | 动态关键帧 + 时空池化压缩 | 视频问答准确率、Prefill 时延与显存 |
| **后训练目标配比** | 仅 SFT | SFT + 一致性奖励 / + 模态路由奖励 / + 延迟惩罚 | 综合质量分 vs P95 端到端时延 Pareto 前沿 |

#### 3.3 复现与门禁规范
- 每次训练与消融实验强制落盘实验清单：代码 commit、数据分片与校验和、模型权重 SHA-256、随机种子、超参配置、自动评测指标与人工抽检样本；
- 训练产出的新 Checkpoint 必须通过 `ummInfer` 统一评测基准与实机延迟/显存回归门禁后，才允许升级线上服务。
