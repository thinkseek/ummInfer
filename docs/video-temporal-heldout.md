## Preflight failures are retained and separated

No failure was converted into a passing quality result:

1. Initial generation failed `scene-boundary threshold coverage: static-square/280`. Inspection showed that replacing the marker without changing the background did not produce the intended scene-scale boundary. The source background was corrected; the `scene_threshold=0.25` assertion remained.
2. The next generation failed the same assertion at `bframe-anchors-heldout/64`. Its post-boundary background was corrected. A subsequent budget-4 audit found the triangle representative weaker than the square/ring representatives. Actual triangle travel was increased from 2 to 3 source pixels per frame; the required anchor rule and thresholds remained fixed. The complete generation then passed. No model request had occurred.
3. The first launched stack failed before model traffic because remote FFmpeg 6 emitted ten `showinfo` records for eight RGB frames. Frozen inputs had already been generated and deeply validated with pinned FFmpeg 5.1.9. The producer now uses committed-byte verification before traffic; independent full decoding remains mandatory in the fresh verifier.
4. The first real serial attempt retained 120 completed/native-valid budget-8 requests but omitted the frozen 4/16 populations because the harness had not propagated `_budgets`. No answers were inspected before correction. Those 120 requests are retained separately and excluded from every result. The corrected schedule was rerun from cold prefixes in full.

The external evidence includes this preflight history in `input/prefreeze-failures.log`.
